# Export and storage contract

Exports are independent of server records and remain available after an instance is deleted. All routes below require the existing owner session (unless authentication is disabled); mutations require the existing Origin/CSRF checks.

- `GET /api/v1/storage`: `{configured, endpoint, region, bucket, prefix, accessKeyId, hasSecret}`. Empty strings when unconfigured. Never returns the secret.
- `PUT /api/v1/storage`: `{endpoint,region,bucket,prefix,accessKeyId,secretAccessKey?}`. Omit/leave the secret empty to retain the existing secret, but only when the endpoint and access key are unchanged. Returns the redacted connection above. Stored privately in the persistent data directory. Path-style S3, HTTP allowed for private VPN endpoints, redirects disabled.
- `POST /api/v1/storage/test`: tests the saved connection by writing, reading/verifying and removing a disposable object. Returns `{ok:true}`; does not create a bucket.
- `GET /api/v1/exports`: `{items: Export[]}` newest first, including deleted instances.
- `POST /api/v1/servers/{id}/exports`: `{scope:"world"|"selected"|"all", paths?:string[], destination:"local"|"s3"}` → 202 `{job: Job}`. Existing job polling contract; successful `job.result` is an Export. The instance MUST be stopped and stays locked through compression, upload and verification. No implicit stop, restart, deletion or EULA changes. Selected paths are instance-relative directories/files, 1–100 paths; no traversal or symlinks. World exports discover world directories by their level.dat files, including dimension folders. Full exports include all regular instance files, including managed server software. Desired server.properties and a server configuration manifest are included for full exports. Symlinks/special files in the selected content cause failure, never follow them. Archives use .tar.gz, bounded at 100 GiB input / 5 GiB compressed / 100,000 entries.
- `GET /api/v1/exports/{id}/download`: attachment stream, including S3 exports through the authenticated backend. No storage credentials or signed links reach the browser.
- `DELETE /api/v1/exports/{id}`: 204 after removing the archive and its catalog record. Refuses deletion while an archived instance pins this restore point (`exports.backup_required`). Does not delete instance files.
- `POST /api/v1/servers/{id}/archive`: `{exportId,confirmDiscardChanges:true}` → 202 `{job}`. Requires a stopped local instance and a matching full S3 export. Re-downloads and verifies its size, SHA-256, gzip/tar structure and manifest before removing local files. The instance record, ID, display icon, settings history and S3 backup remain. Server responses then include `archive:{exportId,archivedAt}`. Newer local changes can be lost, so confirmation is mandatory. No automatic backup or stop is implied.
- `POST /api/v1/exports/{id}/restore`: 202 `{job}`. Requires a full archive and no local instance files; world/selected exports remain downloadable but cannot restore a whole instance. Verifies checksum/limits, extracts to private staging, then publishes the files. Restores the retained identity, backed-up software/launch and a new desired properties revision, preserving current name, network, RAM/CPU and EULA consent. Restoring a permanently removed record recreates its original ID with the backed-up settings and EULA acceptance **false**. The game stays stopped. A local instance is never overwritten; remove/archive it separately first. Successful archive/restore `job.result` is `{server:ServerView}`.

Export: `{id,serverId,serverName,scope,destination,createdAt,size,sha256,fileName,objectKey:string|null}`. Only completed exports appear. S3 uploads are read back and SHA-256 verified before success; temporary local archive is then removed. Failed uploads never delete instance data. Archive history remains independent of instance deletion; connection changes must not silently retarget existing S3 archives (backend refuses while S3 exports exist).

Every server response has `archive:null` while local (older records default to local). Archived records stay in the inventory and return stopped runtime status. Local lifecycle/files/properties/network/resource operations refuse with `server.archived`; display icons remain editable. Permanent DELETE remains a separate local-instance action. A pinned restore point cannot be deleted until the instance is restored. Backup catalogs survive permanent instance deletion and can recreate identities from full archives.

Directory moves and metadata commits use a durable journal. Cancellation retains publication locks until completion, database acknowledgement failures are checked against the persisted record, and interrupted moves are recovered before HTTP admission. Ambiguous or invalid journals are retained instead of guessing which directory to delete. Extraction rejects traversal, links, duplicates, special/sparse entries, unsupported metadata, oversized paths and decompression-limit violations; GNU long paths are processed with explicit bounds. Files and directories are synchronized before publication. Archive and restore observations use the [job progress contract](http-api.md).

UI should clearly separate removing local files from permanently deleting an instance, show local/archived state and backup age, and require a warning about changes since the selected backup. Only full backups offer Restore; a running server must be stopped explicitly. No operation implicitly starts Minecraft or accepts the EULA.

Errors: `exports.invalid` 422, `exports.not_found` 404, `exports.limit` 413, `exports.storage` 502, `exports.busy` 409, `exports.backup_required` 409, `exports.restore_conflict` 409, `exports.invalid_archive` 422, plus existing `server.*` / `files.*` errors. API error messages never include credentials or signed URLs.
