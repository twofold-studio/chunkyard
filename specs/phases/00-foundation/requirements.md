## Edge cases and failure modes

| Case | Expected |
|---|---|
| Two browsers submit setup simultaneously | Exactly one succeeds; other gets `409 setup.already_done` (transactional check). |
| `setup-token` file deleted manually before setup | New token generated on next start; the in-memory token from current run remains valid until restart. |
| DB file locked by another `mcm` process | Startup fails: `error: database is locked (is another mcm running?)`; a `<data>/mcm.lock` file with `flock` is taken first to give this message early. |
| `secret.key` missing but encrypted rows exist | Startup fails with `secret key missing; encrypted settings unreadable` (detected by a `settings` row `crypto.check` = encrypted known value created with the key). |
| Clock jumps backwards | Session expiry uses wall clock; sweeper tolerant; no panics on negative durations (saturating). |
| WS client never reads | Outbound queue fills → connection closed with 1013; server memory bounded. |
| Job handler panics | Caught via `JoinHandle` error → job `failed` with `job.panicked`; runner continues. |
| Migration fails midway | Transactional per migration; process exits 1; DB unchanged for that migration. |
| Login with `mustChangePassword` | Login succeeds; only `/auth/me`, `/auth/password`, `/auth/logout` usable. |
| Attacker hammers `owner` from one IP | That (IP, owner) pair and that IP are throttled; the owner logs in normally from another IP. |
| Lost TOTP device and recovery codes | Operator runs `mcm user reset-password <u> --disable-2fa`. |
| mcm restarts during TOTP enrollment | Pending secret lost (in-memory); user restarts enrollment. |
| Same TOTP code submitted twice within its step | Second attempt rejected (`totp_last_step`). |
| Listen `0.0.0.0` without `public_url` | Startup fails `config.public_url_required`. |
| Very long username/password in login | 422 for username > 32 chars; password > 256 rejected before hashing (DoS guard). |

## Security considerations

- Usernames `^[a-zA-Z0-9_.-]{3,32}$`, case-insensitive unique.
- argon2 verification runs in `spawn_blocking`, bounded by a semaphore (4) to prevent CPU exhaustion via login floods.
- Session and token comparison by hash lookup only; no timing-sensitive string compare needed; setup token uses `subtle::ConstantTimeEq`.
- `Set-Cookie` never sent on bearer-authenticated responses.
- `no_secrets_in_logs` test covers setup token (only the dedicated `warn` line may contain it), passwords, API tokens, session cookies.
- Test hooks are a compile-time feature (`test-hooks`); release builds cannot enable them at runtime. CI `release-features` asserts absence.
- Native runtime single-trust ([security.md](../../architecture/security.md#native-runtime-is-single-trust)) is irrelevant in P0 (no servers) but the permission catalog already marks `files.write`, `content.manage`, `server.settings` as code-execution permissions for P8 to enforce.
- CSP is enforced from the first release; adding any inline script later requires a hash via `kit.csp`.
