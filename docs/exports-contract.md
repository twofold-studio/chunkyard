# Export and storage contract

Exports are independent of server records and remain available after an instance is deleted. All routes below require the existing owner session (unless authentication is disabled); mutations require the existing Origin/CSRF checks.

- `GET /api/v1/storage`: `{configured, endpoint, region, bucket, prefix, accessKeyId, hasSecret}`. Empty strings when unconfigured. Never returns the secret.
- `PUT /api/v1/storage`: `{endpoint,region,bucket,prefix,accessKeyId,secretAccessKey?}`. Omit/leave the secret empty to retain the existing secret, but only when the endpoint and access key are unchanged. Returns the redacted connection above. Stored privately in the persistent data directory. Path-style S3, HTTP allowed for private VPN endpoints, redirects disabled.
- `POST /api/v1/storage/test`: tests the saved connection by writing, reading/verifying and removing a disposable object. Returns `{ok:true}`; does not create a bucket.
- `GET /api/v1/exports`: `{items: Export[]}` newest first, including deleted instances.
- `POST /api/v1/servers/{id}/exports`: `{scope:"world"|"selected"|"all", paths?:string[], destination:"local"|"s3"}` → 202 `{job: Job}`. Existing job polling contract; successful `job.result` is an Export. The instance MUST be stopped and stays locked through compression, upload and verification. No implicit stop, restart, deletion or EULA changes. Selected paths are instance-relative directories/files, 1–100 paths; no traversal or symlinks. World exports discover world directories by their level.dat files, including dimension folders. All exports include all regular instance files, including managed server software. Desired server.properties and a server configuration manifest are included for full exports. Symlinks/special files in the selected content cause failure, never follow them. Archives use .tar.gz, bounded at 100 GiB input / 5 GiB compressed / 100,000 entries.
- `GET /api/v1/exports/{id}/download`: attachment stream, including S3 exports through the authenticated backend. No storage credentials or signed links reach the browser.
- `DELETE /api/v1/exports/{id}`: 204 after removing the archive and its catalog record. Confirmation in UI. Does not affect the instance.

Export: `{id,serverId,serverName,scope,destination,createdAt,size,sha256,fileName,objectKey:string|null}`. Only completed exports appear. S3 uploads are read back and SHA-256 verified before success; temporary local archive is then removed. Failed uploads never delete instance data. Archive history remains independent of instance deletion; connection changes must not silently retarget existing S3 archives (backend refuses while S3 exports exist).

UI: add a compact Exports tab on a server and a global Storage/Exports page so archives remain accessible after deleting servers. Let users choose world/all/selected paths and local/S3, show stopped requirement, job state and verified success. Files selection may supply selected paths; typed newline-separated paths is an acceptable first version. Storage form masks secret, retains it when omitted, and has a Test connection action. No automatic server deletion; existing Delete instance remains explicit. Existing archives can be downloaded and deleted. Restoration is manual extraction for this version; explain full archives include the manifest and managed JAR. Do not claim one-click restore exists.

Errors: `exports.invalid` 422, `exports.not_found` 404, `exports.limit` 413, `exports.storage` 502, `exports.busy` 409, plus existing `server.*` / `files.*` errors. API error messages never include credentials or signed URLs.
