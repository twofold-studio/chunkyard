# CurseForge API and launch contract

Chunkyard 0.4.0 implements this contract. See [CurseForge server packs](curseforge.md) for supported archive formats and operational limits.

The existing wizard request `{software:{type:"curseforge",projectId,fileId}}` selects a **client release**; Chunkyard resolves its linked `serverPackFileId`. API credentials stay on the backend in `CHUNKYARD_CURSEFORGE__API_KEY`; config inspection redacts the key. The catalog lists CurseForge as unavailable with a reason when no key is configured.

- `GET /api/v1/modpacks/curseforge?query=&index=0`: `{items:[{id,name,summary,websiteUrl,logoUrl,downloads}],pagination:{index,pageSize,totalCount}}`. Empty query lists popular packs. Fixed Minecraft game/class, bounded pagination.
- `GET /api/v1/modpacks/curseforge/{projectId}/files`: `{items:[{id,name,gameVersions,serverPackFileId}]}`. Installable client releases with a linked server pack, newest first. Authors can disable third-party downloads; unavailable downloads fail clearly and are never bypassed.
- Existing `POST /api/v1/servers/{id}/install` still accepts an empty body. An optional JSON body supplies `{minecraftVersion?,loader?:"forge"|"neoforge"|"fabric",loaderVersion?,javaMajor?,launch?:LaunchProfile}` for unusual server packs. Overrides are optional; matching versions are detected automatically from pack settings, manifests, installer names and (when needed) the client manifest. Never execute downloaded scripts on the host. Official loader installers run in a temporary isolated Docker container, without starting Minecraft or accepting its EULA. Installing does not start the game. Root wrapper folders are flattened; configuration, mods and scripts become visible through Files. Existing unrelated files are not overwritten. Pack properties are imported without dropping independently saved owner settings.
- `GET /api/v1/servers/{id}/launch`: `{detected:LaunchProfile,current:LaunchProfile,overridden:boolean,dockerImage:string,autoJava:boolean}`.
- `PATCH /api/v1/servers/{id}/launch`: `{profile:LaunchProfile|null,dockerImage?:string|null}` → `{server:ServerView}`. Stopped only. Null profile resets detection; null image restores automatic Temurin selection; omitted image preserves the current policy. Saving removes the owned stopped container, preserving files. New settings apply on Start. A profile can be saved before its target exists (use Files to correct a custom pack); Start validates the target. For uninstalled managed servers, launch overrides are set through install options instead.

`LaunchProfile`: `{mode:"jar"|"args"|"script",path:string,javaMajor:number,jvmArgs:string[],args:string[]}`. Path is instance-relative. Jar launches use Java `-jar`; args launches use Java `@<path>` (modern Forge/NeoForge); script launches use `/bin/bash <path>` inside the game container. Arguments are separate values, never shell command text evaluated on the manager. Managed Java launches apply the Resources heap limits and internal port 25565. Scripts may choose their own JVM flags; the Docker CPU/memory limits still apply. A custom image must provide bash/Java and any tools its script needs. Do not imply that Windows-only batch files work on Linux.

Installed `launch` retains its existing fields and adds an optional `profile:{mode,jvmArgs,args}` and `loader:{type,version}`. For CurseForge, `launch.checksum` is the server-pack ZIP's SHA-256; existing Vanilla SHA-1 and Paper SHA-256 checksums are unchanged. `ServerView` adds optional `launchOverride:LaunchProfile|null`; old records default to null.

The creation wizard uses these endpoints. Settings has a compact Launch row (Jar / Java argument file / Bash script, path, Java, extra JVM/game arguments, optional image, reset detection). An expandable advanced section on the install/retry panel provides the overrides above. API keys stay out of the browser; retries retain the same instance and preserve EULA ownership. Failure messages cover `software.download_unavailable`, `software.pack_unsupported`, `software.files_conflict`, `software.install_failed` and `server.launch_missing`.

Survey evidence (2026-11-14): inspected the top 20 results from CurseForge's Minecraft modpack search sorted by total downloads and their published server ZIP central directories and bootstrap text files. RLCraft and RAD ship no ready loader; ATM10 uses NeoForge, ATM8/9/6 and SkyFactory/SevTech use Forge installers; Better MC and Prominence use variables-driven Forge/Fabric bootstrap scripts; Cave Horror includes a prepared Forge `unix_args.txt`; DeceasedCraft/Cursed Walking include Windows-oriented startup files; Vault Hunters has a setup script and manifest. Fabulously Optimized's sampled artifact has client-oriented contents and no server bootstrap, so no universal server compatibility claim is warranted. Selected release IDs and archive layouts can change: inspect current metadata, not a hard-coded pack-name allowlist. Sources: [CurseForge REST API](https://docs.curseforge.com/rest-api/), pack authors' linked server files, [AllTheMods scripts](https://github.com/AllTheMods/Server-Scripts).
